ℹ About This Benchmark

NetTrace runs the same simulated traffic through two implementations of the same routing/threat-detection logic, so the "tax" of the pattern-driven design can be measured live rather than assumed.

Model A — Baseline
Plain procedural code. Threat checks and metrics are inline conditionals with no abstraction layer between them and the routing loop.
Model B — Pattern-driven
Packets are built through a Factory (per-protocol packet construction is delegated instead of branched on inline), and threat detection / metrics run through an Observer — the routing loop just notifies listeners rather than knowing what they do.
What "Observer Overhead" means
The measured extra time Model B spends dispatching to its Observer-pattern listeners, versus Model A's inline check doing the equivalent work. It's the real, per-request cost of that abstraction — not a hardcoded figure.
How the hop route ties to Model A/B
Model A's displayed hop delays are scaled by the actual measured ratio between this request's Model A and Model B benchmark averages (model_a_ratio in the API response) — not a fixed constant. The "Core AI Firewall" hop's threat flag is decided by a real call to AiThreatClassifier, the same trained logistic regression used in the packet log below, not just an on/off attack-mode flag.
